# Rationale: P6.SingleFailureRobust

## What the statement says
For every finite `V : Type` (`Fintype V`, `DecidableEq V`) and `G : SimpleGraph V` with
`DecidableRel G.Adj`, with `n = patchCount V` and `m = corridorCount G = G.edgeFinset.card`:
if `2 ≤ n` and `SurvivesSingleFailure G`, then `n ≤ m`. Here
`SurvivesSingleFailure G := G.Connected ∧ ∀ e ∈ G.edgeSet, (G.deleteEdges {e}).Connected`.

## Hypotheses (complete list)
- `V : Type`, `[Fintype V]`, `[DecidableEq V]`, `G : SimpleGraph V`, `[DecidableRel G.Adj]`.
- `2 ≤ Fintype.card V`.
- `G.Connected`.
- For every `e ∈ G.edgeSet`, `(G.deleteEdges {e}).Connected`.

## Why it is the right target
It states the cost of redundancy: surviving any single corridor loss costs at least one corridor more than
the `n − 1` of a dendritic (tree) network. Together with `P6.MinimalNetwork` it makes the
HDFM trade-off precise. A tree is cheapest and has no redundancy. Redundancy costs at least one extra
corridor, and one extra is enough for the cycle. The intended proof uses `P6.MinimalNetwork` parts
1–3: n ≤ m + 1; if m + 1 = n then G is a tree; a connected graph on ≥ 2 vertices has an edge;
removing it disconnects a tree. That contradicts the hypothesis. The module restates what it needs and does not import the other module.

## Attainment witnesses (checked by `decide`)
- The triangle `⊤ : SimpleGraph (Fin 3)`: `2 ≤ 3`, connected, connected after deleting any edge,
  `m = 3 = n`.
- The 4-cycle `cycle4` on `Fin 4` (edges 0–1, 1–2, 2–3, 3–0): same hypotheses, `m = 4 = n`.
So the bound `n ≤ m` is tight for n = 3 and n = 4. The n-cycle attains it in general, but that is
not part of the statement.

## Check of n = 2 (done by hand before proposing)
On two vertices the only simple graphs are the empty graph, which is not connected, and the single
edge 0–1, which is connected but disconnected by removing that edge. So no graph satisfies the
hypotheses, and the statement holds vacuously for n = 2. The module checks the relevant facts by
`decide`: `⊤ : SimpleGraph (Fin 2)` is connected, deleting `s(0,1)` disconnects it, and
`⊥ : SimpleGraph (Fin 2)` is not connected.

## Negative control
The hypothesis `2 ≤ n` cannot be dropped. On one vertex (`⊥ : SimpleGraph (Fin 1)`) the graph is
connected, it has no edge to lose (the survival clause holds vacuously), and `m = 0 < 1 = n`. The module
checks this by `decide`. Note that `n = 0` is excluded anyway because `Connected` requires
`Nonempty V`.

## What the statement does not settle
- It counts corridors only: no costs, lengths or qualities, and no claim about the cheapest
  robust network by cost.
- It concerns single *edge* failures only. Loss of a patch (vertex), or of two corridors at once
  (k-edge-connectivity for k ≥ 3), is not covered.
- It does not characterise the extremal graphs (connected graphs with m = n that are 2-edge-connected are exactly
  the cycles). That could be a later statement.
- Nothing about real corridor failure modes, species use or independence of failures.
- Classical graph theory, not a new theorem.

## Consistency check (not a claim)
To make sure the target is not false as written, I wrote a throwaway Lean proof of `Statement` in a
scratch directory outside `out/`, and it compiled under the pinned toolchain. That proof is not part of
this proposal, no proof is claimed, and the proving task stays open.
