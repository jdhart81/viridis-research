# Rationale: `P1.Bridge` (L3, the raster bridge)

**Status: proposal only. Nothing here claims a proof of `Statement`.**

## What the statement says

For every finite raster `B : Finset (ℤ × ℤ)`:

1. the set of enclosed 4-components of `ℤ² \ B` is finite, and
2. `(enclosed B : ℤ) = C8 B - euler B`.

Definitions (all in the module, nothing assumed):

- `G4`, `G8`: the 4- and 8-adjacency graphs on `ℤ²`, built with `SimpleGraph.fromRel`
  from `|dx| + |dy| = 1` and `|dx| ≤ 1 ∧ |dy| ≤ 1`. `fromRel` removes loops.
- `barrierGraph B = G8.induce B`, and `C8 B = Nat.card` of its connected components.
- `complementGraph B = G4.induce Bᶜ`. **The complement is taken in all of `ℤ²`**, not in a window.
- `IsEnclosed c := c.supp.Finite`. **A component is enclosed exactly when it is finite.**
  `enclosed B = Nat.card {c // IsEnclosed c}`.
- `euler` (with `Pixel`, `corners`, `vertices`, `hEdges`, `vEdges`) is restated character for
  character from the sealed module `ViridisStatements.P1.BitQuad` (L1), checked with `diff`. The
  module imports only `Mathlib`. **Change from the 2026-11-03 draft:** that draft imported
  `ViridisStatements.P1.BitQuad`, and the verifier rejected it before probing because the
  module's object file was not available in its proposal environment. Once the import resolves
  there, the restated block can be replaced by `open ViridisStatements.P1.BitQuad` with no change in meaning.

## Why this is the right target

It is the raster form of the `FaceCount` hypothesis that the machine-checked core of
*Trees Cannot Cut* (`DualCorridor.lean`) assumes: bounded compartments = first Betti number
of the barrier = `C8 − χ`. It has no topology in it. Everything is a finite graph-theoretic
or counting statement about `ℤ²`, so it can be proved in Mathlib without Alexander duality.
Defining "enclosed" as "finite" fixes the exterior convention from the brief without using
a bounding box, so the statement does not depend on how a raster is cropped.

Clause (1) is there on purpose. `Nat.card` of an infinite type is `0`, so without clause (1)
the equation could be met vacuously if there were infinitely many finite components. Clause (1)
rules that reading out. (It is true: every finite component lies in the bounding box of `B`.)

## Relation to the ladder

- L1 `P1.BitQuad` (sealed, proved 2026-10-28) provides `euler` and makes `Δχ` under one
  insertion local.
- L2 `P1.Insertion` is the inductive step. L3 clause (2) follows from L2 by induction on
  `B.card` (`Finset.induction_on`) from the empty raster, where both sides are `0`. Conversely
  L3 (2) implies L2 at once, so L2 and L3 (2) are equivalent given the base case. The split
  exists to organise the proof, not to make the statements different in strength.
- Clause (1) is a separate, mostly routine lemma: a component outside the bounding box
  contains a ray and is infinite.

## Controls in the module

By `decide`, on a computable bounded-box flood-fill model (`boxC8`, `boxEnclosed`). The
statement does not use this model.

| raster | C8 | χ | enclosed | note |
|---|---|---|---|---|
| empty | 0 | 0 | 0 | base case |
| 3×3 ring (witness) | 1 | 0 | 1 | |
| 2×2 block (negative control 1) | 1 | 1 | 0 | `K₄` has circuit rank 3, but nothing is enclosed |
| N/S/E/W diamond (negative control 2) | 1 | 0 | 1 | 4-adjacency graph has no edges, but the centre is enclosed under (8,4) |
| diagonal pair | 1 | 1 | 0 | corner contact counts for `C8` and for `χ` |

**Proved for the semantic definitions themselves**, with no use of the box model
(namespace `Controls`): `enclosed ring = 1`, `enclosed block = 0`, `enclosed diamond = 1`,
`enclosed ∅ = 0`, `C8 ring = C8 block = C8 diamond = 1` and `C8 ∅ = 0`. From these, the identity
`enclosed = C8 − χ` is checked for the ring, the block and the diamond. The proofs use two
general lemmas. A free horizontal ray makes a component infinite (`infinite_of_ray`). A pixel
whose four 4-neighbours are all barrier is a finite component on its own (`isolated`).

**Bitmask model (new in this draft, namespace `Mask`).** A 7×7 box is encoded as a 49-bit
natural number, and the kernel evaluates `C8`, the enclosed count and `V − E + F` by bit
operations. `decide` checks the three controls in this model, and checks that **all 512
subsets of a 3×3 window** satisfy `enclosed = C8 − χ`. The same identity is checked for all
512 subsets again, each inside a closed 16-pixel ring around the window. Agreement of this model
with the semantic definitions is not proved either.

Outside Lean, `code/bridge_check.py` (rewritten tonight) recomputes both sides independently. It finds 0
failures on all 65,536 subsets of a 4×4 box and on 3,000 random rasters up to 12×12. This is
evidence, not proof.

## Known gaps

- Agreement of the box model with `C8`/`enclosed` is not proved. Only the semantic controls
  above connect the two.
- The (8,4) pairing matters. Under (4,4) the diamond would have `C4 = 4`, which breaks the
  identity, and the module records `numComponents adj4 diamond = 4`.
