# Proposal `P2.Tempo`: the Tempo stewardship-cadence kernel

## What the statement means

The Tempo kernel recommends how often to visit or intervene at a site. The haste cost
`h > 0` penalises acting too often and the neglect cost `n > 0` penalises waiting too long.
For a cadence `t > 0` the kernel's cost is

    Sigma(t) = h / t + n * t.

The module defines exactly the five quantities that `context/Tempo_runner.py` computes:
`Sigma` (runner `cadence_cost`), `optimum = sqrt(h/n)` (`optimal_cadence`),
`floor = 2 * sqrt(h*n)` (`tempo_floor`), `normalizedCost = Sigma / floor` (`normalized_cost`)
and `tax = cosh(log(t / optimum))` (`haste_neglect_tax`). `Statement` says that for every real
`h > 0`, `n > 0`:

1. `Sigma_strictConvexOn`: `Sigma h n` is strictly convex on `Set.Ioi 0`.
2. `tempo_floor`: `floor h n ≤ Sigma h n t` for every `t > 0`.
3. `tempo_optimum`: `Sigma h n (optimum h n) = floor h n`.
4. `tempo_unique_minimizer`: if `t > 0` and `Sigma h n t = floor h n` then `t = optimum h n`.
5. `haste_neglect_cosh`: `(u + 1/u)/2 = cosh(log u)` for every `u > 0`; and its kernel form
   `normalizedCost h n t = tax h n t` for every `t > 0`.
6. `governability_tax`: for every `t > 0`, `normalizedCost h n t = cosh(log(optimum h n / t))`;
   `1 ≤ tax h n t`; and `tax h n t = 1 ↔ t = optimum h n`.

The six parts follow the six theorem names in `context/Tempo_function.json`, in order.

## Is the brief's version correct?

I checked every part against the runner and the published example. **All six parts in the brief
are mathematically true.** The checks:

- With `s = sqrt h` and `r = sqrt n`, we have `sqrt(h n) = s r`, `sqrt(h/n) = s/r` and
  `Sigma(t) − 2 s r = (s − r t)^2 / t`. Parts (2), (3) and (4) follow: the gap is zero exactly
  when `t = s/r`.
- For `x > 0`, `cosh(log x) = (x + 1/x)/2`. Putting `x = t/t*` with `t* = s/r` gives
  `(t/t* + t*/t)/2 = (n t + h/t)/(2 s r) = Sigma(t)/floor`. Since `cosh` is even, the same holds
  with `t*/t` in place of `t/t*`.
- `cosh y ≥ 1`, with equality only at `y = 0`. And `log x = 0` with `x > 0` only at `x = 1`.
- `h/t` is strictly convex on `(0, ∞)` when `h > 0`, and `n t` is linear.
- Published example `h = 4, n = 1, t = 2`: optimum `sqrt 4 = 2`, floor `2 sqrt 4 = 4`,
  cost `4/2 + 2 = 4`, normalised cost `1`, tax `cosh(log 1) = 1`. All match `expected_outputs`.

Parts (5) and (6) as written in the brief do **not match the deposited theorems with those
names**. The brief's (5) is the deposited `governability_tax`, with the ratio inside `log` turned
upside down. The brief's (6) has no deposited counterpart. The deposited `haste_neglect_cosh` is
the bare identity `(u + 1/u)/2 = cosh(log u)`.

**Change.** Each numbered part now holds both the brief's content and the deposited signature of
the same name:

- part (5) is the deposited identity together with the brief's `normalizedCost = tax`;
- part (6) is the deposited orientation `normalizedCost = cosh(log(optimum / t))` together with
  the brief's `1 ≤ tax` and `tax = 1 ↔ t = optimum`.

A proof of the sealed statement would then imply every deposited theorem (instantiate `h = n = 1`
for the bare identity) and every part of the brief. Parts (1)–(4) match the deposit unchanged,
with `A ↦ h`, `B ↦ n`, `τ ↦ t` and the cost folded into `Sigma`, `floor` and `optimum`. Those
definitions unfold exactly to the deposited expressions. If Justin prefers the brief's six-part
form, deleting the two deposited conjuncts gives exactly that form.

I checked feasibility privately. A scratch Lean derivation of the full `Statement` (a file in
`/tmp`, outside `out/`) compiled under the pinned toolchain. This only shows that the target is
not false. **It is not a claim of proof**, and no proof is submitted.

Two choices of form:

- Part (4) is stated as "attains the floor ⇒ equals the optimum", which is the deposited form.
  Together with (2) it says that `sqrt(h/n)` is the unique minimiser on `(0, ∞)`.
- Part (6) states the equality case as an `↔` for `t > 0`.

Two observations, neither of which changes the statement:

- Because of (5), the tax facts in (6) are the same as parts (2) and (4) for `normalizedCost`.
  The redundancy is deliberate, since the kernel reports both numbers.
- The runner tests `at_optimum` with a floating-point `is_close` and rounds its outputs to 12
  digits. The statement uses exact real arithmetic. Whether the floating-point code conforms is
  not covered.

## Why this is the right target

It covers every quantity the kernel outputs, other than the boolean `at_optimum`, and uses the
runner's own formulas. Each of the six registry theorem names corresponds to one numbered part,
so a later proof can be checked part by part against the registry. Every definition lives inside
`ViridisStatements.P2.Tempo`. The module imports only Mathlib and declares no axioms.

## Relation to the ladder

Within P2 this is the first kernel with no source in the canon repository. The earlier sealed
statements (Carbon Continuity, Restoration, Afforestation, Harmonization) restated canon theorems
whose files were in hand. Here the statement was reconstructed from the runner first and only
then compared with a deposited source found during this session. The sequence is the same as
before: proposal (P2-T014), then sealing by Justin, then a proof (P2-T015, which waits on this
task). The mathematics sits at the bottom of the difficulty ladder.
**The results are elementary:** parts (2)–(4) are the two-term arithmetic–geometric mean
inequality `h/t + n t ≥ 2 sqrt(h n)` with its equality case, and parts (5)–(6) are the identity
`cosh(log x) = (x + 1/x)/2` together with `cosh ≥ 1`. The value of sealing it is assurance: the
kernel's outputs would then rest on a kernel-checked statement instead of an unreplayed deposit and
a retired receipt.

## What the statement does not settle

**The model `Sigma(t) = h/t + n t`, with constant haste and neglect costs, is an assumption about
a stewardship programme, not a result.** Nothing here shows that real monitoring costs scale
like `1/t` and `t`, that they are constant over time, or that `h` and `n` can be measured. A proof
would establish only the mathematics applied to the model.

There is also a unit point. The registry gives both `h` and `n` the unit "cost per cycle". For
`h/t + n t` to add like terms, `h` and `n` must have different units: if `h` is a cost, `n` must
be cost per time squared. This affects the documentation of the inputs, not the mathematics.

## Controls (examples in the module)

The examples are closed by `norm_num` and short rewrites, not `decide`, because equality on `ℝ`
is not decidable. This is the same practice as the sealed P2 modules.

- Witness, published example `h = 4, n = 1, t = 2`: optimum `2`, floor `4`, cost `4`,
  cost = floor, normalised cost `1`, tax `1`.
- Witness, `h = 1, n = 4`: optimum `1/2`, floor `4`, `Sigma(1/2) = 4`.
- Witness for (5)/(6) off the optimum: at `h = 4, n = 1, t = 1` the normalised cost is `5/4`, and
  `cosh(log(optimum/1)) = cosh(log 2) = 5/4`.
- Negative control, off the optimum (`h = 4, n = 1, t = 1`): cost `5 > 4` = floor, and normalised
  cost `> 1`.
- Negative control, `t > 0` is needed: `Sigma 4 1 (−2) = −4 < 4`, so (2) fails for negative
  cadences.
- Negative control, `n > 0` is needed: with `n = 0`, Lean's `x/0 = 0` makes the optimum and the
  floor `0`. Then at `t = 1` the normalised cost is `0` while the tax is `1`, so (5) fails. Also
  the tax equals `1` at `t = 1 ≠ 0`, so the equality clause of (6) fails.
- Negative control, `h > 0` is needed for (1): with `h = 0`, `Sigma` is linear, and
  `Sigma(2) = (Sigma(1) + Sigma(3))/2`, so strict convexity fails.
