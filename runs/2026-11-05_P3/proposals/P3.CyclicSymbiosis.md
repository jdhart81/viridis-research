# Rationale: P3.CyclicSymbiosis

## What the statement says
`N` partners sit on a cycle indexed by `Fin N`. Partner `i` ships a by-product flow `x i` to
partner `i+1` at cost `c i · x i` and receives its predecessor's flow, which is worth
`v i · x (prev i)` to it, where `prev i = (i + N - 1) mod N`. Net benefit is
`net c v x i = v i · x (prev i) - c i · x i`. `Statement` asserts that for every `N ≥ 2` and
all `c, v : Fin N → ℝ` with every `c i > 0` and every `v i > 0`:

  `(∃ x, (∀ i, 0 < x i) ∧ ∀ i, 0 < net c v x i) ↔ ∏ i, c i < ∏ i, v i`.

## Hypotheses, all listed
- `2 ≤ N`; `∀ i, 0 < c i`; `∀ i, 0 < v i`.
- Model assumptions (Run-128 standing assumptions carried over): one period, linear separable
  payoffs, zero disagreement utilities, no externalities, known constant coefficients, and a
  single directed cycle (each partner has exactly one supplier and one customer).

## Agreement with the canon (N = 2)
Run-128 (`context/ReciprocityCorridor.lean`, doi:10.5281/zenodo.21971047) has
`uX = vX*y - cX*x`, `uY = vY*x - cY*y` and
`ProductCondition vX cX vY cY := cX * cY < vX * vY`. The module copies `ProductCondition`
verbatim and checks two things, by `simp` and `decide`, in `example`s that compile with the
module. First, `CycleProductCondition ![cX, cY] ![vX, vY] ↔ ProductCondition vX cX vY cY`.
Second, `net` at `x = ![x, y]` equals `uX` for partner 0 and `uY` for partner 1. So the `N = 2`
case of `Statement` is exactly Run-128 Theorem 2 (`strict_corridor_nonempty_iff_product_condition`),
with the corridor replaced by its equivalent bilateral-benefit form (Theorem 1).

## Why it is the right target
It is the natural N-partner corridor. Feasibility of a strictly beneficial loop depends only
on whether the cycle's value multiplier `∏ v_i / c_i` exceeds one. The partners do not need to
be pairwise feasible. In the 3-partner sanity check, one partner has `v < c`, yet the cycle is
feasible. The flow must then be tuned: the uniform flow fails, while `x = (1, 9/20, 2/5)`
works. The statement is self-contained over Mathlib, so sealing it does not depend on the
canon file.

## Controls
- `prev` on `Fin 3` and `Fin 2` is checked by `decide`.
- `N = 2` agreement with `ProductCondition` and with `uX`, `uY` (`simp`).
- Witness: `c = (1,1,1)`, `v = (4,1/2,1)` satisfies `1 < 2`. The uniform flow gives partner 1 a
  negative net, while `x = (1, 9/20, 2/5)` gives nets `(3/5, 1/20, 1/20)`, all positive.
- Negative control: `c = (2,2,2)`, `v = (1,1,1)` fails the condition, and the uniform flow
  harms partner 0.
- Negative control (boundary): `c = v = (1,1)` gives equal products, which fail the strict
  condition.

## What the statement does not settle
It makes no claim about any real cost, value, partner, material or industrial park. It does not
cover networks other than a single cycle (branching, several suppliers), capacity limits on
flows, transport losses, multi-period dynamics, or how the surplus is divided among partners.
Run-128's Nash-midpoint result has no N-partner analogue here. The equivalence also holds for
`N = 1` (a self-loop, where the condition reads `c < v`), but the brief and the industrial
reading start at `N = 2`, so the hypothesis is kept.
