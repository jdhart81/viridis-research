# Rationale: P3.CascadedRecovery

## What the statement says
A stream passes `n` recovery stages in series, and stage `i` recovers the share `r i` of what
reaches it. The virgin share after the cascade is `virginShare r = ∏ i, (1 - r i)`
(`r : Fin n → ℝ`). For all `r i ∈ [0, 1]`, `Statement` asserts:

1. `0 ≤ virginShare r ≤ 1`;
2. for every `m` with `r i ≤ m` for all `i` and `m ≤ 1`: `(1 - m)^n ≤ virginShare r`;
3. `(1 - ⨆ i, r i)^n ≤ virginShare r`, which is the bound with the largest stage recovery;
4. for every stage `j`: `virginShare r ≤ 1 - r j`;
5. for `j`, `k` with `k ≠ j`, `0 < r k` and `r j < 1`: `virginShare r < 1 - r j`.

## Hypotheses, all listed
- `n : ℕ` arbitrary (including `n = 0`); `∀ i, 0 ≤ r i`; `∀ i, r i ≤ 1`.
- Part 2: `∀ i, r i ≤ m` and `m ≤ 1`.
- Part 5: `k ≠ j`, `0 < r k`, `r j < 1`.
- Model assumption: stages act multiplicatively and independently on what reaches them.

## Design choices
- The maximum is written `⨆ i, r i` (Mathlib's `iSup` on `ℝ`). For finite nonempty `Fin n`
  this is the true maximum. For `n = 0` it is `sSup ∅ = 0`, and both sides equal `1`, so no
  `0 < n` side condition is needed. Part 2, the uniform-bound form, avoids `iSup` altogether.
  It is included because a kernel usually knows an upper bound on stage recovery, not the
  exact maximum.
- The strictness clause names the "other stage" `k` explicitly, matching the brief: the
  cascade is strictly better than stage `j` alone exactly when some other stage recovers
  something and `j` does not already recover everything.

## Controls (examples, `norm_num`)
- `r = (1/2, 1/2)`: share `1/4`, which equals the lower bound and is strictly below the
  single-stage `1/2`.
- `r = (1/2, 1/4, 0)`: share `3/8 > (1/2)^3`.
- Negative control `r = (0, 1/2)`: share equals `1 - r 1`, so strictness needs `r k > 0`.
- Negative control `r = (1/2, 1)`: share `0 = 1 - 1`, so strictness needs `r j < 1`.
- Negative control `r = (2, 1/2)`: negative share, so `r i ≤ 1` is necessary.
- Negative control `r = (-1, 1/2)`: share above `1 - 1/2`, so `r i ≥ 0` is necessary for part 4.

## Ladder
This is the second rung. The effective cascade recovery `1 - virginShare r` is a valid `r` for
P3.LoopMassBalance (part 1 puts it in `[0,1]`).

## What the statement does not settle
It makes no claim about any real stage recovery rate or material. It does not model stage
interactions (contamination that lowers downstream recovery), quality loss, energy cost of
stages, or whether adding a stage is worth its cost. Pairing a stage's cost with
P3.RecoveryWorkFloor is a later task.
